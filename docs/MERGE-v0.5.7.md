# v0.5.7 合并决策记录

v0.5.7 由两条线合并而成：公开发布线 v0.5.3–v0.5.6（`main`），以及从 v0.5.2
分出的本地开发线（`wip/local-line-from-v0.5.2`）。两边都修了同一个问题时，取更稳妥的方案，
并让另一边的测试继续通过。

| 领域 | 采用 | 说明 |
| --- | --- | --- |
| 入口与收纳边界 | v0.5.6 | 固定宽度的 `MenuBarStatusHandle`，加上一个独立的 3 pt 边界 `ShelterBar.Boundary`（默认位置 = 入口 + 38），用来适配 macOS 26 合成菜单栏。本地线的单项借位、自动隐藏行和缓存都移植到这套结构上。 |
| 收起保护 | v0.5.6 + 本地线 | `ensureHandleOnResidentSide`/`hasSafeHandle` 保留；在全屏或自动隐藏时，入口位于隐藏的菜单栏行上也视为安全。 |
| 刘海 | 两边都用 | 释放点检查（`isDropAllowed`，本地线）和完整原生窗口检查（`isDestinationFrameAllowed`，v0.5.6）都要通过才发送输入；边界左侧被遮挡时，退回 `moveBoundary(after:)`。 |
| 移动失败 | 本地线 | 只隔离单个失败项，不整排展开。v0.5.6 的刘海提示文案（`movementFailureMessage`）照常显示。两个 v0.5.6 测试的期望从 `.degraded`/展开改为 `.idle`/收起，并在测试里加了注释。 |
| 移动验证 | 本地线 | 验证次数从 8 次增加到 16 次，适应较慢的系统重排。 |
| 窗口枚举 | v0.5.6 | `currentWindows` 使用 `.optionAll`，配合 `resolvePair` 等待一致的原生窗口；只需要屏幕上窗口的调用方（菜单打开器、可见入口）改用 `onScreenWindows()`。 |
| 图标对比度 | 两边都用 | 模板判定沿用本地线（含 alpha 归一化）。中性多灰阶图标沿用 v0.5.6 的随外观自适应反相，彩色为主的图标沿用本地线的色调标记加浅色衬底。磁盘缓存为自适应图标记录 `adaptive`，读取时重新生成，保证重启后仍能自适应。 |
| 权限 | 两边都用 | v0.5.6 的输入权限门和“授予输入权限”跳转设置保留；屏幕录制改为辅助功能生效后立即询问（本地线）。 |
| 签名 | 本地线 | 固定使用“ShelterBar Self-Signed”签名，DR 校验见 `docs/RELEASE.md`。v0.5.6 的 DMG 依赖检查和布局保留。 |
| 外接显示器几何（合并后自测发现） | 新修复 | v0.5.6 的 `trailingControlFrame` 要求整个方块落在菜单栏区域内；外接显示器菜单栏高 24 pt，图标位于 y+3，因此入口/边界都定位失败，单项借位退回整排展开且无法收起。改为按中心点判断所在行、按水平范围判断显示器，并新增测试。 |
