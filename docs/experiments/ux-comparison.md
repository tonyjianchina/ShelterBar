# v0.5.13 体验优化比较

基线为 `ffb198c`（v0.5.12 / Build 36）。三个方向在独立 Git 分支和工作树开发与验证；最终建议是合并三个互补改动，发布为 v0.5.13 / Build 37。

| 候选 | 已确认问题 | 结果与证据 | 选择 |
| --- | --- | --- | --- |
| `codex/shelterbar-smoothness` | 展示缓存图标仍同步查询第三方 AX 标题；AXPress 的等待占住主线程 | 20 次缓存命中的 AX 标题查询从 20 次降为 0；模拟慢 AXPress 时主线程可以继续执行；原验证和超时保留 | 优先合入，直接针对交互停顿 |
| `codex/shelterbar-shelf-ui` | 状态消息和可选录屏提示替换整排图标 | 原生 SwiftUI 渲染及控件测试确认提示/拖拽期间保留图标；40 图标可横向滚动，320 pt 布局不重叠 | 合入，直接改善可用性 |
| `codex/shelterbar-feature-polish` | 后台每次都重新下载安装包才判定当前版本；完成提示打断图标操作 | 相同已验证资产的 fixture 从 3 次请求降为 1 次、准备安装从 1 次降为 0 次；变化或手动检查仍完整验证 | 合入，减少后台 I/O |

主仓库最初未改动，独立分支验证后在 `codex/shelterbar-ux-recommended` 整合。用户随后授权更新 GitHub、官网与自动升级，因此将通过最终回归的整合结果发布到主分支。

性能数字来自受控延迟或数据 fixture，不能当成第三方菜单整体打开速度或真实网络耗时。原生渲染截图是合成测试数据，并非持续屏幕采集。没有为测试修改用户的菜单栏布局或 TCC 授权。

实际运行的 Build 36 空闲采样为 CPU 0%、物理内存约 32.7 MB，主线程主要等待事件；这些改动针对交互和重复工作，没有把空闲状态误诊为持续忙循环。

进一步优化应先采集具体第三方应用、显示器配置和操作路径的耗时，再决定是否调整扫描或菜单检测。此次保留实时位置验证和失败恢复，避免为了减少等待引入错误点击。

详细实验：[流畅度](smoothness.md)、[界面](shelf-ui.md)、[更新检查](feature-polish.md)。
